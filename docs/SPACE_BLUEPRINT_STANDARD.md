# Space Blueprint Standard

## Purpose
Defines the common blueprint behavior for every `spaces/*/BLUEPRINT.md`.

## One-space blueprint framing
- target space: 100% of its approved parent area shown clearly
- neighboring spaces: context only
- normal context strip: **5–15% of sheet depth** beyond the target boundary
- context must be lighter/greyed/hatched and labeled
- do not fully render all four neighboring spaces unless the user asks for a multi-space/master blueprint

## Required information
- drawing title / space name
- north arrow
- parent area in m² and ft²
- L1 coordinate/block/ring authority
- architecture area schedule
- internal IDs/labels
- access/circulation
- drainage/water
- electrical/lighting
- CCTV/security/safety where applicable
- legend
- revision/status
- PROVISIONAL tag for unapproved internal dimensions

## Required consistency
The blueprint, IMAGE.md and ARCHITECTURE.md must describe the same permanent layout. If they conflict, resolve the authority conflict before drawing.

## Blueprint views
Use the views that make the space understandable:
- plan/top view
- dimensions/space-management
- system overlays
- sections
- elevations where buildings/walls/sheds exist
- technical details for water, treatment, equipment, structures or crop/animal layouts

## Neighbor context
The four side neighbors come from L1 geometry and the space's architecture/image files, not visual guessing.
